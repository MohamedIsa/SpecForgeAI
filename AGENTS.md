# SpecForge Workspace Project Context & Guidelines

Welcome to the **SpecForge AI** codebase. This file defines the global project context, architectural guidelines, and codebase standards for this repository.

---

## 1. Project Overview & Context
SpecForge AI is a monorepo web application that acts as an enterprise Virtual Tech Lead. Users upload Business Requirements Documents (BRDs). The system runs an interactive AI clarification chat session to resolve ambiguities before coding starts, validates target tech stacks, and generates a structured ticket backlog on an interactive Kanban board with context-complete AI Dev Prompts.

---

## 2. Locked Monorepo Architecture
All code must be organized inside the workspace as follows:
*   `/apps/backend/`: Fastify server integrated with tRPC routers.
*   `/apps/web/`: React application (Vite + Tailwind CSS v4 + Shadcn UI).
*   `/apps/mobile/`: Expo companion mobile application.
*   `/packages/config-typescript/`: Shared, strict base TypeScript configurations.
*   `/packages/design-tokens/`: Autogenerated styling constants (`@specforge/design-tokens`).

---

## 3. Strict Development Rules
*   **Tech Stack Lock:** Fastify + tRPC, React (Vite), Expo, PostgreSQL, Terraform, DeepSeek API (AI layer), Tailwind CSS v4, and Shadcn UI.
*   **Type Safety:** Strict mode enabled. The type `any` is strictly prohibited in TypeScript code.
*   **UI Framework:** Web components must be built using Shadcn UI and styled with Tailwind CSS v4 theme tokens from `@specforge/design-tokens`.
*   **Vertical Feature Slices:** Every feature ticket must be implemented as a vertical slice (Backend DB/tRPC procedure + Frontend UI component + integration wiring) so that it can be validated end-to-end visually and functionally.
*   **Test Driven:** Unit or integration tests are required for all non-trivial business logic, routing, or state transitions.
